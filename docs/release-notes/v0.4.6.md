# Scrinium v0.4.6 release notes

**Upgrade every Scrinium binary that reads a repository before any claim with authorship `tool` is written into it.** Older binaries (v0.4.5 and earlier) refuse such a claim file. One such file makes `claim_list` fail for the whole claims directory there: it returns `malformed_canonical_record` and lists no claims at all, not only the new one. `claim_get` on that claim returns `malformed_canonical_record`, and `claim_lint` reports `malformed_claim_file`. This is measured behaviour of the v0.4.5 binary.

- New claim authorship kind `tool`: deterministic software created the claim, with no model and no person writing it. `origin` names the program (for example `nuntius`) and is required, as it is for every kind. The kind is accepted by canonical claim validation, `claim_create` over CLI and MCP, and `claim_lint`.
- Authorship stays provenance only. `tool` asserts nothing about truth, grants no assessment, never changes assessment, freshness, or lifecycle, and needs the same session, governance, and `expected_revision` as any other write. Unknown kinds, including `Tool` and `tools`, are still refused by name.
- `capabilities` gains `authorship_kinds`, the list of kinds this binary accepts (additive within `scrinium.capabilities/v1`). Check it before writing a `tool`-authored claim; a binary without that key does not accept `tool`.
- Compatibility: `tool` is a new enumerated value inside `scrinium.claim/v1` and `scrinium.claim-create/v1`. The schema version is unchanged and existing records are unaffected. Claims that do not use `tool` read the same in old and new binaries.
- Development: `make verify` now ends with `rulefloor check` over the new `RULE-FLOOR.md` and requires Rulefloor v0.9.2 on PATH. It fails, and never skips, when Rulefloor is missing or is another version.
