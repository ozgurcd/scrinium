# Scrinium v0.2 Public API

Status: implemented v0.2 contract

Scrinium exposes generic claim, source, and durable-session operations through MCP and the direct CLI. Validator-specific commands are intentionally absent: `claim_validate` resolves the named binding through the validator registry.

## Operations

Claims: `claim_create`, `claim_get`, `claim_list`, `claim_update`, `claim_add_evidence`, `claim_set_validation_policy`, `claim_validate`, `claim_supersede`, `claim_withdraw`, `claim_lint`.

Sources: `source_register`, `source_get`, `source_list`, `source_refresh`, `source_migration_status`.

Sessions: `session_begin`, `session_continue`, `session_status`, `session_finish`, `session_abandon`, `session_list`.

The CLI uses the same names. Simple reads accept identifiers such as `--claim-id` or `--source-id`. Complex inputs use exactly one of `--input FILE` or `--input-json JSON`. Session-dependent operations require `--session ID`. `--json` produces one JSON document on stdout; machine errors also use stdout and return non-zero.

Input schemas:

- `scrinium.claim-create/v1`
- `scrinium.claim-update/v1`

- `scrinium.claim-policy/v1`

- `scrinium.claim-supersede/v1`
- `scrinium.claim-withdraw/v1`
- `scrinium.source-register/v1`

Result schemas:

- `scrinium.claim-result/v1`
- `scrinium.claim-list/v1`
- `scrinium.claim-validation-run/v1`
- `scrinium.claim-lint/v1`
- `scrinium.source-result/v1`
- `scrinium.source-list/v1`
- `scrinium.source-migration-status/v1`
- `scrinium.session-result/v1`
- `scrinium.session-list/v1`
- `scrinium.capabilities/v1`
- `scrinium.error/v1`

Inputs reject unknown fields, duplicate keys, unsupported schemas, multiple JSON values, and documents over 1 MiB. Input files must be regular non-symlink files. Canonical `Claim` and `SourceRecord` objects are embedded deliberately in result envelopes; their own `scrinium.claim/v1` and `scrinium.source/v1` schemas remain authoritative.

## Claim reads and mutations

`claim_get` and every claim mutation result contain:

```json
{
  "schema_version": "scrinium.claim-result/v1",
  "claim": {},
  "state": {
    "lifecycle": "active",
    "assessment": "sourced",
    "freshness": "current",
    "reasons": []
  },
  "revision": "sha256:..."
}
```

Mutation inputs require `expected_revision`. Read, mutate using that revision, and retain the returned revision. A stale revision returns `scrinium.error/v1` with code `conflict`, the expected revision, and the current revision. Scrinium does not retry, merge, or use last-write-wins.

`claim_validate` accepts `selection: "binding"` plus `binding_id`, or `selection: "required"` for all required bindings of one claim. The application reads the claim and revision, executes external validation without a claim lock, then persists by CAS. A concurrent claim change rejects the obsolete result.

## Trust presentation

Claim results never provide a numeric confidence score. They expose lifecycle, assessment, and freshness independently, followed by typed evidence, validation policy, complete validation history, and revision. `verified` plus `stale` is never flattened to `verified`.

Rulefloor static passes are observations. Supported Rulefloor execute passes may satisfy verification-grade bindings when execution and fingerprints authenticate. Gograph is capped at observation assurance; it evaluates Go structure, not runtime or business correctness. `cannot_evaluate` never counts as pass and removes current verified presentation when it replaces a required pass.

## Errors

Stable public error codes are:

`not_found`, `conflict`, `invalid_input`, `governance_denied`, `session_required`, `session_closed`, `validator_unavailable`, `cannot_evaluate`, `malformed_canonical_record`, and `internal_error`.

Expected domain failures are semantic MCP tool errors rather than JSON-RPC protocol failures. CLI machine mode returns a versioned error document and a non-zero status without human prose on stdout.

## Capabilities

`capabilities` reports preferred and deprecated operations, every public schema, deterministic guarantees, heuristic-review scope, configured validator availability, descriptors, binding schemas, assurance ceilings, and current write-governance policy. Validator absence is discoverable and does not prevent startup.

## Compatibility

v0.1 page/wiki tools, source migration/apply helpers, legacy session aliases, and `enforce-agents` remain available during v0.2 and are marked deprecated where applicable. Markdown is a human view; page mutation is not the preferred canonical knowledge workflow.
